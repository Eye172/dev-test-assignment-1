# Orbit GTM Studio handover

Orbit is an independent synthetic-data founder workspace. Its required six-screen journey records five independently saved GTM sections and turns them into a 30-day plan. Completion remains exactly saved complete sections / 5; neither completed forms nor tasks establish commercial validation.

The integrated journey supports free-form and guided entry, locally extracted PDF/DOCX/PPTX/text material, owner-only AI interpretation, profile confirmation and recoverable launch. Continue with AI is the primary action; an explicit offline alternative is available. Unlock resumes the pending analysis, and actual model-generated questions cover relevant unanswered facts. Known profile fields are filtered out. Clarification answers remain separate private context for every specialist. Source text has explicit extraction/coverage limits. Confirmation wins over earlier extraction. Startup and AI request identifiers survive lost acknowledgements and reloads; paid specialists require an explicit choice. Launch states distinguish working, locked, failed and ready-for-review results.

Six OpenAI specialists interpret, research/compare, strategize, monetize, design experiments and independently critique. They exchange typed persisted artifacts through an orchestrator, with one bounded correction round. Relevant direct/indirect alternatives and the current workflow are compared on case-specific axes. Captured passages retain source time, hash and limitations; vendor assertions remain reported claims. Hypotheses and decisions retain revisions, options, counterarguments, reasons, observations and reopening conditions. New evidence reopens review without rewriting accepted decisions.

A plan preview reconciles pending old suggestions and protected human/completed work against weekly capacity, separate currency budgets, dependencies and measurement deadlines. One AI plan is active at a time. Unknown costs/capacity remain explicit; accepting a conditional plan does not prove feasibility. Replacing it with the rule plan is deliberate and preserves history. The original 8–10-suggestion rule engine works without a paid API key.

Next.js App Router, React, strict TypeScript and Zod share domain contracts in src/lib/domain. Server route handlers delegate to transactional PostgreSQL services; PGlite runs the same SQL locally. Versioned migrations serialize across instances. Credentials remain server-side. Six private analysis displays and eight public dashboard plates have separate validated customization registries.

Public demo links permit editing synthetic profiles, saved strategy and tasks. AI briefs, material, observations, memory, source captures, prompts and usage history require the signed HttpOnly owner gate. Accepted content becomes public only through reviewed application. Commercial use needs tenant authentication/authorization and agreed data boundaries; private Black Orbit systems and payment processing are outside this prototype.

Run npm run verify and npm run test:e2e. Real API evaluations are explicitly paid and excluded from CI; deterministic fixtures and mocked preflight UI responses are labelled separately. Read [ACCEPTANCE.md](ACCEPTANCE.md) and [SUBMISSION.md](SUBMISSION.md) for final evidence and known limits. Deploy the standalone server or Vercel with PostgreSQL; [DEPLOYMENT.md](DEPLOYMENT.md) documents environment, checkpoints and health checks. Docker is supplied but was not executed on this Windows host.

The [one-page PDF](../output/pdf/orbit-gtm-studio-handover.pdf) is regenerated from scripts/build-handover.py, rendered and checked. scripts/package-submission.py creates a committed-tree source ZIP, the matching PDF, revision record and SHA-256 checksums, checking for local credentials and private/build files. The package is prepared for the owner to submit; no external evaluator is contacted.
