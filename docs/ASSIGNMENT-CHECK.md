# Сверка с исходным ТЗ

Источник: `Orbit_GTM_Studio_Developer_Test_Assignment.docx` в корне предоставленного проекта, разделы 02–08. Это сверка исходного задания; последующие пожелания владельца об AI и трёх интерфейсах рассматриваются отдельно.

| Требование | Реализация и проверка |
| --- | --- |
| Welcome, создание, профиль с уникальным URL, стратегия, дашборд, 30-дневный план | Все шесть маршрутов сохранены. `e2e/workspace.spec.ts`, `e2e/v4.spec.ts` проходят основной путь и три интерфейса. |
| Обязательные поля профиля, B2B/B2C/B2G, три стадии, необязательный корректный URL | Серверные Zod-схемы; `tests/backend.test.ts` проверяет пустые значения, перечисления и протокол URL; браузер проверяет редактирование. |
| Пять независимо сохраняемых разделов | ICP, предложение, до трёх каналов с причинами и экспериментом, монетизация, ровно три полные гипотезы с риском и методом проверки. Незаконченные черновики разрешены; `tests/backend.test.ts` и `e2e/workspace.spec.ts`. |
| Заполнение = завершённые разделы / 5 × 100% | Единственная формула в `src/lib/domain/completion.ts`; пробелы и неполные записи не считаются. Дополнительный радар проработки плана не заменяет обязательный процент. |
| Сохранённые решения, пробелы, следующие действия | Дашборд во всех трёх интерфейсах; `e2e/v4.spec.ts` и проверки доступности. |
| 6–10 задач по прозрачным правилам; неделя, статус, результат | Генератор даёт 8–10 задач по сохранённой стратегии, без обязательного платного API. `tests/backend.test.ts` проверяет пустой и заполненный варианты. |
| Изменение статуса, сохранение прогресса, безопасная повторная генерация | База хранит состояния; завершённые, изменённые и пользовательские задачи сохраняются, заменённые остаются в истории. SQL- и браузерные тесты. |
| Реальная база, refresh, повторное открытие URL | PostgreSQL; локально файловый PGlite с тем же SQL. Есть тест повторного открытия базы после закрытия движка и полный браузерный путь. |
| Loading/empty/error/validation, мобильная версия, навигация | `e2e/frontend-regressions.spec.ts`, `e2e/draft-safety.spec.ts`, `e2e/accessibility.spec.ts`, `e2e/welcome.spec.ts`. Дополнительно проверяются конфликты версий, медленные ответы и сохранность черновиков. |
| Не объявлять непроверенную гипотезу подтверждённой | Заполнение полей и выполнение задач не помечают гипотезы validated. `tests/v4.test.ts`. Иллюстрация распределения гипотез на лендинге не записывает доказательства в рабочий проект. |
| Демо без авторизации явно обозначено, нечувствительные примеры | Требование §06 сохранено одной короткой строкой внизу лендинга. Повторные бейджи и пояснения убраны по просьбе владельца. Кнопка примера и отдельные рабочие копии сохранены. |
| Env, модульность, схема, маршруты, ограничения | `.env.example`, README, `docs/CONTRACT.md`; ключи находятся только в локальном/серверном окружении. Упаковщик проверяет архив на реальные значения ключей. |
| Репозиторий, публичное приложение, заполненный пример, README, одностраничная передача | Репозиторий и текущий публичный production существуют; PDF и исходный архив подготовлены. Новая v4-версия находится в PR #13 и локально. Продвижение v4 в публичный production ещё не выполнено: ранее владелец оставил merge/promotion отдельным согласуемым шагом. Защищённый Vercel preview не считается общедоступной демонстрацией v4. |

Функциональные требования исходного ТЗ сохранены. Платный AI — отдельное расширение владельца; исходный путь работает без него. Указанное выше состояние публикации является ограничением поставки новой версии, а не пройденной проверкой.
